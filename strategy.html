What this is

ORB v3 is an opening-range breakout day-trading system on liquid Nasdaq names. The opening range is the first regular-session hour (one 60-minute bar). After that, whenever a scan sees a 60-minute bar close above the range high (long) or below the range low (short), it sends a market entry with an attached stop and take-profit, and everything is flat the same day.

How trades are entered / executed

Signal

  • Long: the first post-OR hourly bar that opens at or below ORH and closes above it. Reference entry = max(ORH, that bar’s open) — i.e. ORH.
  • Short: the first post-OR hourly bar that opens at or above ORL and closes below it. Reference entry = ORL.
  • Polling fallback: if no such bar exists but the latest bar (which can be the still-forming hour) is closing beyond the range, that counts too, with the latest price as the reference entry.
  • Shorts are allowed (allow_short: true). No trend, ATR or time-of-day filter.
  • Once a symbol has been entered it is not entered again that day.
  • Breakout must still hold (implemented Oct 9, 2026): right before entry the current price (latest trade, else ask/bid, else last bar close) must still be above ORH for a long or below ORL for a short; otherwise the entry is skipped as skip_breakout_not_holding.
  • Minimum live reward-to-risk 1.5 (implemented Oct 9, 2026): using that current price against the fixed stop and target, reward ÷ risk must be ≥ min_live_rr: 1.5; otherwise skip_poor_rr (x.xx < 1.5). Stop and target themselves are unchanged.

Entry cutoff

Hard entry cutoff at 12:45 PT, enforced in code (implemented Oct 9, 2026). Rules key no_entry_after_pt: "12:45" (defaults to 12:45 if missing): at or after 12:45 PT no new entries are placed and candidates are reported as skip_entry_cutoff. 12:44 PT can still enter; 12:45 cannot. So the 12:52 scan can never open a trade after LIVE’s 12:50 flatten. (The backtest’s entry_cutoff filter stays null; this is a live-trading guard.)

Scanner cadence

Weekday routines run every 15 minutes at :07, :22, :37, :52 from 6:07 AM to 12:52 PM PT. Scans before 7:30 only confirm the OR isn’t ready; the first scan that can enter is 7:37 PT. LIVE and PAPER use separate routines, keys and state files. Each scan:

  1. Verifies its Alpaca keys with a read-only call (backup copy if they fail; see Execution).
  2. Refreshes hourly bars and computes each symbol’s OR, width filter and breakout status.
  3. Runs a dry-run plan, then the live --arm: daily −2R halt → 12:45 PT cutoff → concurrency gate → OR-volume priority → breakout-still-holding → live R:R ≥ 1.5 → size on current price → cash gate → bracket submit.
  4. Writes a status/heartbeat file, posts actionable alerts, and refreshes the dashboard.

Orders, state, sizing

  • Entry is an Alpaca market order, DAY, bracket class: take-profit limit at the target and stop (stop-market) at the OR midpoint, both rounded to the cent.
  • LIVE state: orb_v3_live_state.json · PAPER state: orb_v3_paper_state.json (never mixed). Default mode is paper; LIVE needs an explicit --live.
  • Keys: separate LIVE and PAPER keys, stored on the trading computer and verified before every run (never pasted into chat; paper never falls back to live).
  • Risk per trade 1.5% of account equity, sized on the current price (implemented Oct 9, 2026): shares = (equity × 1.5%) / |current price − OR midpoint|, so actual risk stays ≤ 1.5% even on a late fill.
  • Notional cap 16% of equity per symbol: shares ≤ equity × 16% / current price. Quantity = the smaller of the two, rounded down to whole shares. With OR-mid stops the 16% cap is usually the binding limit, so actual risk is often well below 1.5%.
  • Cash gate (both tracks): entries are taken in priority order while cash lasts; any entry whose notional exceeds remaining account cash (+$1 tolerance) is held as skip_insufficient_cash. No margin.
  • Max 6 concurrent × 16% ≈ 96% of equity, so a full book fits in cash.
  • PAPER uses the same 6 / 16% / 1.5% sizing as LIVE.

Late-fill protection (implemented Oct 9, 2026). Scans run every 15 minutes, so price can be past the breakout level by the time the order goes in. Right before submitting, the code re-checks with the current price: it skips if price is back inside the range (skip_breakout_not_holding) or if reward ÷ risk to the fixed stop/target is below 1.5 (skip_poor_rr), and it sizes on current price → stop so risk stays ≤ 1.5%. A market order can still slip a little past the price checked.

Long example

ORH = 120, ORL = 116 → mid (stop) = 118 Breakout bar closes above 120 → reference entry = 120.00 → R = 2.00 Target = 120 + 2.5 × 2.00 = 125.00 · Stop = 118.00 Planned: −1R / +2.5R If price is 121.50 when the order would go in: risk 3.50, reward 3.50 → 1.00 < 1.5 → skip_poor_rr If price is 120.60: risk 2.60, reward 4.40 → 1.69 ≥ 1.5 → enter

Short example

Same OR: ORH = 120, ORL = 116 → mid (stop) = 118 Breakout bar closes below 116 → reference entry = 116.00 → R = 2.00 Target = 116 − 2.5 × 2.00 = 111.00 · Stop = 118.00 (above entry)

Sizing example

Equity $50,000 · ORH 120 · stop 118 · current price 120.60 (risk 2.60/share) Risk sizing: 50,000 × 1.5% / 2.60 = 288.5 → 288 shares Notional cap: 50,000 × 16% / 120.60 = 66.3 → 66 shares ← binding Order: 66 shares (≈ $7,960 notional, ≈ $172 at risk = 0.34% of equity)

No overnight. No second trade on a symbol already traded that day.

Daily −2R halt (implemented Oct 9, 2026). Before every arm, each track recomputes today’s realized R from Alpaca fills (per closed ORB trade: P/L ÷ planned 1R, where 1R = qty × |planned entry − stop|) and stores it in its own state file keyed by the PT date. When the total is ≤ daily_loss_limit_R: −2.0, new entries are blocked for the rest of that day and the scan prints DAILY HALT: realized −X.XR ≤ −2R for alerts. Open positions keep their brackets and are still flattened at EOD.

Execution / reliability

  • Trading computer first: all scans, EOD flattens and checks run on the bot's own computer; keys are verified with a read-only Alpaca call before every run.
  • Key fallback: only if local keys are missing or rejected are fresh copies pulled from the owner's PC, with an alert naming the reason. Trading halts only if both fail.
  • Morning health check (7:37 PT): OR/bar freshness, disk, code environment, keys and Alpaca access; problems alerted in one line.
  • Heartbeat: each run publishes a status file alongside each dashboard; the owner's PC checks it every 10 minutes from 7:40 AM to 1:00 PM PT and alerts if it goes quiet (>35 min) or reports a problem.
  • 12:58 PT backstop flatten: run from the owner's PC directly through Alpaca if anything is still open at the close.
  • Wrong-account guard: EOD refuses to mark “flat” if the broker suddenly shows a fresh $50,000 / 0-position account while state says positions were open (likely wrong keys).

Risks & limitations

  • Real money on LIVE. Losses are possible on any day; the backtest drawdown is not a cap.
  • Daily −2R halt counts only closed trades; open losers don’t count until they exit, so a day can end below −2R.
  • Late fills: the live R:R and breakout checks use the price just before submit; a market order can still slip beyond it.
  • 12:45 PT cutoff: an entry at 12:44 has only minutes before the EOD flatten.
  • Data: signals depend on free Yahoo Finance hourly bars, which can be delayed, missing or revised.
  • Slippage: market entries and stop-market exits can fill worse than planned, especially at the open of a bar or in fast moves.
  • Concentration: up to 6 positions in correlated large-cap tech; a broad move can hit several stops together.
  • PAPER universe is a fixed Sep 23, 2026 snapshot; index changes aren’t picked up automatically. Paper fills are simulated and more forgiving than live.
  • Operations: relies on scheduled routines and broker/API uptime; late or failed runs are mitigated (heartbeat, 12:58 backstop) but not eliminated.
